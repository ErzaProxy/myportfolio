How the four weeks connect

The course follows one idea in order. The OS sits between programs and hardware (week 1). It can pretend to be hardware for a whole other OS (week 2). It runs programs as processes, which you create with C calls like fork() (week 3). Inside a process, threads share memory, and shared memory causes race conditions (week 4).

Week 1 · Silberschatz Ch 1 & Ch 2

Introduction & Operating-System Structure

What an OS is, how hardware tells it things (interrupts), how it protects itself (dual mode), what it offers programs (system calls), and the ways a kernel can be organised.

What an operating system is ch1·s5–10

An OS is a program that acts as an intermediary between the user and the computer hardware. It has three goals: run user programs and make problems easier to solve, make the system convenient to use, and use the hardware efficiently.

Four components
Hardware (CPU, memory, I/O) → Operating system → Application programs → Users
Kernel
"The one program running at all times on the computer." This is the core of the OS.
System program
Ships with the OS but isn't part of the kernel.
Application program
Any program not associated with the OS.
Middleware
Frameworks on top of the OS that give developers extra services (databases, multimedia, graphics). Common on mobile OSes.
Two viewpoints
The OS is a resource allocator (it manages CPU, memory and I/O) and a control program (it controls how user programs run).

Interrupts & I/O ch1·s12–19

The CPU and device controllers share memory through a common bus. Each device controller has a local buffer and an OS device driver. The controller moves data between its device and its buffer. When it finishes, it raises an interrupt to tell the CPU.

  • An interrupt transfers control to the interrupt service routine through the interrupt vector, which is a table holding the addresses of all service routines.
  • The interrupt architecture must save the address of the interrupted instruction. The OS saves the registers and program counter so it can resume afterwards.
  • A trap (or exception) is a software-generated interrupt. It is caused by an error (such as divide by zero) or by a request (a system call).
  • The OS is interrupt driven.
Synchronous I/O

Wait for completion

Control returns to the user program only when the I/O finishes. The CPU idles with a wait instruction, and only one I/O request can be pending at a time.

Asynchronous I/O

Return immediately

Control returns without waiting. A device-status table tracks each device's type, address and state. The program uses a system call when it wants to wait.

DMA (Direct Memory Access) is used for fast devices. The controller copies a whole block straight into main memory without the CPU, so there is one interrupt per block instead of one per byte.

Storage ch1·s20–28, s41

  • Bootstrap program: runs at power-up. It is stored in ROM/EPROM (firmware), initialises the system, and loads the kernel.
  • Main memory (DRAM) is the only large storage the CPU can access directly. It is random access and volatile.
  • Secondary storage is large and non-volatile. HDDs use platters divided into tracks and sectors. NVM devices are faster than HDDs.
  • The hierarchy trades off speed, cost and volatility. From fast to slow: registers → cache → main memory → NVM → HDD → optical → tape.
  • Caching copies data into faster storage temporarily. Check the cache first; on a miss, copy the data in. Main memory acts as a cache for secondary storage.
  • Units: 1 KB = 1,024 bytes, 1 MB = 1,024², and so on. Networks are measured in bits.

Multiprogramming, dual mode & the timer ch1·s29–35

Multiprogramming (batch)
Keeps several jobs in memory so the CPU always has something to run. When a job waits for I/O, the OS switches to another job.
Multitasking (timesharing)
Switches jobs so often that users can interact with them. Response time should be < 1 second. This leads to processes, CPU scheduling, swapping and virtual memory.
Dual-mode operation
The hardware provides a mode bit: 0 = kernel, 1 = user. Privileged instructions only run in kernel mode. A system call switches to kernel mode, and returning from it switches back to user mode.This is how the OS protects itself from user programs.
Timer
Stops a process from running forever (for example, an infinite loop). The OS sets a counter (a privileged instruction), and when it reaches zero it raises an interrupt that gives control back to the OS.

What the OS manages ch1·s36–45

Process

A program is passive, a process is active. The OS creates and deletes, suspends and resumes processes, and provides synchronization, communication and deadlock handling.

Memory

Tracks which parts of memory are in use and by whom, decides what moves in and out, and allocates and frees memory.

File system & mass storage

Files and directories, access control, mapping files to disk, backups. Also mounting, free-space management, allocation, disk scheduling and partitioning.

I/O subsystem

Buffering holds data while it is being transferred. Caching keeps copies in faster storage. Spooling overlaps one job's output with other jobs' input.

Protection controls which processes and users can access resources. Security defends against internal and external attacks. Systems identify users with a user ID and group ID. Privilege escalation lets a user switch to an effective ID with more rights.

The command-line interpreter (shell) reads a command and runs it. A command can be built into the shell, or it can just be the name of a program. With program names, you can add new commands without changing the shell. GUIs were invented at Xerox PARC.

System calls ch2·s13–27

A system call is the programming interface to OS services. Programs rarely call them directly. They use an API instead: the Win32 API, the POSIX API (UNIX, Linux, macOS) or the Java API. For example, the C library's printf() calls the write() system call.

  • Each system call has a number. The system-call interface keeps a table indexed by those numbers.
  • The caller doesn't need to know how the call is implemented. It only follows the API.

Three ways to pass parameters

1 · Registers

The simplest method. It fails when there are more parameters than registers.

2 · Block / table

Put the parameters in a block of memory and pass the block's address in a register. Linux and Solaris use this.

3 · Stack

The program pushes the parameters and the OS pops them. Block and stack methods have no limit on the number or length of parameters.

Arduino is single-tasking with no OS: a boot loader loads one sketch. FreeBSD is multitasking: the shell calls fork(), then exec(), then waits. Exit code 0 means no error and >0 is an error code.

System services, linkers & loaders ch2·s28–34

  • System programs cover file management, status information, file modification, language support, program loading, communications and background services. Most users see the OS through these, not through system calls.
  • Background services (daemons, services, subsystems) start at boot and run in user context, not in the kernel.
  • Source → compiler → relocatable object file → linker (combines object files and libraries) → executable → loader (puts it in memory). Relocation assigns the final addresses.
  • Dynamically linked libraries (DLLs on Windows) are loaded when needed and shared by every program that uses them.
  • Apps are OS-specific because each OS has its own system calls and file formats. Workarounds: interpreted languages (Python), a VM (Java), or recompiling standard C. The ABI is the binary-level equivalent of an API.

Design principles ch2·s35–37

User goals
Convenient, easy to learn, reliable, safe, fast.
System goals
Easy to design, implement and maintain. Flexible, reliable, error-free, efficient.
Policy
What will be done. Example: interrupt every 100 seconds.
Mechanism
How to do it. Example: the timer.Keep them separate so a policy change (100 → 200) doesn't need a new mechanism.
Implementation
Usually a mix: assembly at the lowest level, C for the main body, C/C++ and scripts for system programs. Higher-level code is easier to port but slower.

Boot & debugging ch2·s52–59

  • Building Linux: download source → make menuconfig → make (produces vmlinuz) → make modules → make modules_install → make install.
  • Boot: execution starts at a fixed memory address. A bootstrap loader (BIOS, or UEFI on modern systems) finds and loads the kernel. GRUB lets you pick a kernel. Some systems use two steps: a boot block, then the loader.
  • Debugging: log files, a core dump when an app fails, a crash dump when the kernel fails. Profiling samples the instruction pointer periodically.
  • Tools: top / Task Manager (performance), strace (system calls), gdb (source-level debugger), perf, tcpdump (network packets), BCC/eBPF (tracing).
  • Kernighan's Law: debugging is twice as hard as writing code, so if you write code as cleverly as you can, you can't debug it.

Check yourself · week 1

What is the difference between an interrupt and a trap?
Hardware devices raise interrupts (for example, a controller finishing I/O). A trap (exception) is software-generated, caused by an error such as divide by zero or by a system call.
Why can't a user program just set the mode bit to kernel?
Changing the mode is a privileged instruction. The only way into kernel mode is a system call, trap or interrupt, and those jump to OS code, not user code.
Why does DMA reduce CPU load?
The controller copies a whole block straight to memory and raises one interrupt per block, instead of interrupting the CPU for every byte.
Name the three ways to pass system-call parameters. Which ones have no size limit?
Registers, a memory block/table (address passed in a register), and the stack. Block and stack have no limit.
Give one benefit and one cost of a microkernel.
Benefit: easier to extend and port, more reliable and secure because less code runs in kernel mode. Cost: message passing between user space and the kernel adds performance overhead.
"Switch processes every 10 ms" is a policy or a mechanism?
A policy (what to do). The timer interrupt that makes it happen is the mechanism.

Virtualization, Shell Script & C Basics

How one machine pretends to be many, the techniques that make that possible, and the two tools you'll use in the lab: Bash scripts and GCC.

The three parts of a VM system ch18·s4–5

The idea is to abstract the hardware of one computer into several separate execution environments. Each environment gets a virtual copy of the machine.

Host
The underlying hardware system.
VMM / hypervisor
Creates and runs VMs by giving each one an interface identical to the host. Paravirtualization is the exception.
Guest
The process given a virtual copy of the host. Usually a whole operating system.

History: first seen on IBM mainframes in 1972. Formal requirements for a VMM: programs see an environment essentially identical to the real machine, run with only minor slowdown, and the VMM stays in complete control of resources. In the late 1990s Intel CPUs got fast enough, and Xen and VMware appeared.

Exam trap

Type 1 runs on bare metal. Type 2 runs on top of a host OS. VirtualBox and VMware Workstation are Type 2. ESX is Type 1. Containers/zones are not VMs, because only one kernel runs.

Benefits ch18·s10–11

  • Isolation: the host is protected from VMs, and VMs from each other, so a virus is less likely to spread.
  • Freeze / suspend / snapshot / clone: save a state, restore it, or copy a VM and run both.
  • Templating: build an OS + app image once, then deploy many copies.
  • Live migration: move a running VM to another host without interrupting users.
  • Put all of these together and you get cloud computing.

Building blocks ch18·s12–22

Most VMMs keep a VCPU for each guest. It holds the CPU state as the guest believes it to be, and is loaded when the guest is switched onto the real CPU.

Technique 1

Trap-and-emulate

The guest kernel runs in real user mode but in virtual kernel mode. When it attempts a privileged instruction, that causes a trap. The VMM takes over, performs the operation for the guest, and returns.

User-mode code runs at native speed. Kernel-mode code is slower.

Technique 2

Binary translation

Needed for CPUs like older x86. Their popf instruction behaves differently in user mode without trapping, so trap-and-emulate can't catch it.

When the guest is in virtual kernel mode, the VMM reads ahead, runs normal instructions natively, translates "special" ones, and caches the translations. Booting Windows XP took 950,000 translations, a 5% slowdown.

Memory

Nested page tables (NPT)

The guest thinks it controls its page tables. The VMM keeps a per-guest NPT that mirrors them and makes it active when that guest runs. Downside: more TLB misses, so it is slower.

Hardware

Intel VT-x (2005) · AMD-V (2006)

Adds host and guest CPU modes, so binary translation is no longer needed. The CPU maintains the VCPU and supports NPT, DMA and interrupts in hardware.

OS components under virtualization ch18·s37–44

CPU scheduling
Guests get VCPUs. Usually there aren't enough physical CPUs, which is called overcommitment. Cycle stealing means a guest's 100 ms time slice might really take a second, so its time-of-day clock drifts.
Memory
VMware ESX uses three methods: double paging, a balloon pseudo-driver that makes the guest release memory, and de-duplication of identical pages.
I/O & network
Direct device access, DMA pass-through. Networking uses bridging (direct access) or NAT.
Storage
A guest disk is a disk image file. Copy the file to clone the guest, move the file to move it. P-to-V and V-to-P convert between physical and virtual formats.
Live migration
1) Source connects to target. 2) Target creates a guest (VCPU and so on). 3) Send read-only pages. 4) Send read-write pages and mark them clean. 5) Resend pages that became dirty, and repeat. 6) When that loop gets short: freeze, send the final VCPU state and dirty pages, start on the target. 7) Target confirms, source terminates its copy.

Research topics: unikernels (app + libraries + kernel services compiled into one binary), and partitioning/separation hypervisors such as Quest-V and Jailhouse for real-time and safety-critical systems.

Check yourself · week 2

What's the difference between a Type 1 and a Type 2 hypervisor? Give an example of each.
Type 1 runs directly on the hardware in kernel mode (VMware ESX, XenServer). Type 2 is an app on a host OS (VirtualBox, VMware Workstation).
Why couldn't trap-and-emulate virtualize older x86 CPUs?
Some instructions, such as popf, act differently in user mode without causing a trap, so the VMM never gets control. Binary translation (later VT-x/AMD-V) solved this.
How is paravirtualization different from full virtualization?
The guest OS is modified to know about the VMM and cooperate with it (for example, hypercalls). The VMM doesn't present an exact copy of the hardware, but performance improves.
Are containers/zones virtual machines?
No. They are application containment: only one kernel (the host's) runs. Apps are isolated with their own network stack, users and resources.
What do $# and $? hold?
$# is the number of arguments. $? is the exit status of the last command, where 0 means success.
What does nama = "Andi" do in Bash?
It fails. Bash tries to run a command called nama with arguments = and Andi. Variable assignment must have no spaces: nama="Andi".
List the four GCC stages in order.
Preprocessing → compiling → assembling → linking.

C Language & Processes

A process is a program in execution. This page covers what's inside one, the states it moves through, how fork() creates new ones, how they talk to each other, and the C and text tools from the lab handout.

A program is passive: an executable file on disk. It becomes a process, which is active, once it is loaded into memory. One program can be several processes, for example when several users run the same program.

Process states ch3·s8–9

Only one process per core can be running. Many can be ready or waiting.

New
Being created.
Ready
Waiting to be assigned a processor.
Running
Instructions are executing.
Waiting

Exam trap

Waiting never goes straight to running. When the I/O finishes, the process goes back to ready and waits for the scheduler. An interrupt (such as the timer) moves running → ready. Requesting I/O moves running → waiting.

  • The process scheduler picks the next process for a CPU core. Its goal is to maximize CPU use.
  • Ready queue: processes in memory, ready to run. Wait queues: processes waiting for an event. Processes move between queues.
  • Context switch: save the old process's state into its PCB and load the new one's. This time is pure overhead because no useful work happens. It takes longer with a more complex OS or PCB, and depends on hardware support.
  • Mobile: early iOS ran one foreground process with limited background tasks. Android allows background work through services, which have no UI and use little memory.

Interprocess communication ch3·s29–50

Processes are either independent or cooperating. Reasons to cooperate: information sharing, computation speedup, modularity, convenience. Cooperating processes need IPC, which comes in two models.

Model A

Shared memory

A region of memory is shared between processes. It is controlled by the user processes, not the OS. It is fast, but the processes must synchronize their own access.

Model B

Message passing

No shared variables. The OS provides send(message) and receive(message). Messages can be fixed or variable size. Easier to use and works across a network.

Producer–consumer with a bounded buffer

This version is correct but only holds BUFFER_SIZE − 1 items. Adding a shared counter lets it fill every slot, but that causes a race condition. Week 4 covers it.

An unbounded buffer means the producer never waits. With a bounded buffer, the producer waits when the buffer is full. In both cases the consumer waits when it is empty.

Message-passing design choices

ChoiceOption 1Option 2
NamingDirect: send(P, msg). Links are automatic, exactly one link per pair, exactly two processes per link.Indirect: send(A, msg) through mailbox/port A. A link can have many processes, and a pair can share several links.
BlockingBlocking = synchronous. A blocking send waits until the message is received. A blocking receive waits until a message is available.Non-blocking = asynchronous. Send continues immediately. Receive returns a message or null.
BufferingZero capacity: sender waits for the receiver (rendezvous). Bounded: sender waits if the link is full.Unbounded: sender never waits.

Blocking send + blocking receive = rendezvous. If P1 sends to mailbox A shared with P2 and P3, who gets the message? Options: allow only two processes per link, allow one receiver at a time, or let the system pick a receiver and tell the sender.

IPC in real systems ch3·s51–70

POSIX shared memory
shm_fd = shm_open(name, O_CREAT | O_RDWR, 0666); → ftruncate(shm_fd, 4096); sets the size → mmap() maps it and returns a pointer you read and write through.
Mach
Everything is a message, even system calls. Each task gets two ports at creation (Kernel and Notify). Uses mach_msg() and mach_port_allocate(). If the mailbox is full: wait forever, wait n ms, return immediately, or cache the message temporarily.
Windows ALPC
Advanced local procedure call, same machine only. The client opens a connection port and sends a request. The server creates two private ports and returns a handle to one of them.
Ordinary pipe
Unidirectional (write end → read end). Needs a parent–child relationship. Windows calls these anonymous pipes.
Named pipe
Bidirectional, no parent–child relationship needed, several processes can use it. Available on UNIX and Windows.
Socket
An endpoint = IP address + port, for example 161.25.19.8:1625. Ports below 1024 are well known. 127.0.0.1 is loopback. Java has TCP (connection-oriented), UDP (connectionless) and multicast sockets.
RPC
Remote procedure call. A client-side stub finds the server and marshals the parameters, and the server stub unpacks them. XDR handles big- vs little-endian. The goal is exactly once delivery, not at most once. A matchmaker service connects client to server.

Pointers & arrays C Lanjut p2–3

A pointer is a variable that stores the address of another variable. &x gives the address of x. *p dereferences p, giving the value at that address. You need pointers when a function must change the caller's variables.

An array name is the address of its first element. Pointer arithmetic: p + i is the address of element i, and *(p + i) is its value.

Check yourself · week 3

What's the difference between a program and a process?
A program is a passive executable file on disk. A process is active: a program loaded into memory with a program counter, stack, heap, data and so on.
What does fork() return, and where?
0 in the child, the child's PID (>0) in the parent, and -1 if it fails.
Zombie or orphan: the child exits but the parent never calls wait()?
Zombie. An orphan is when the parent terminates first without calling wait().
Why is context-switch time called overhead?
While saving one PCB and loading another, the system does no useful work for any process.
Which state does a process go to when its I/O completes?
Ready, not running. It has to wait for the scheduler to dispatch it.
Ordinary pipe vs named pipe?
An ordinary pipe is unidirectional and needs a parent–child relationship. A named pipe is bidirectional, needs no relationship, and can be shared by several processes.
Why does the circular buffer only hold BUFFER_SIZE − 1 items?
"Full" is detected as (in+1) % SIZE == out. One slot must stay empty so that full can be told apart from empty (in == out).
What does sed 's/a/b/' leave unchanged in a a a?
The 2nd and 3rd a. Without g, only the first match on each line is replaced, so the output is b a a.

Threads & Synchronization

Threads are several flows of control inside one process. They share code, data and files, but each has its own stack, registers and program counter. That sharing is what makes them cheap, and it's also what makes them dangerous.

Why threads ch4·s4–7

Most modern apps are multithreaded. A word processor might have one thread updating the display, one fetching data, one spell checking, and one answering the network. Process creation is heavy-weight; thread creation is light-weight. Kernels are multithreaded too.

Shared by all threads

Code section, data section (globals), open files, other OS resources.

Private to each thread

Thread ID, program counter, register set, stack.

Responsiveness
The app keeps running if part of it blocks. This matters most for UIs.
Resource sharing
Threads share process memory automatically, which is easier than setting up shared memory or message passing.
Economy
Cheaper to create than processes, and switching threads costs less than a process context switch.
Scalability
A process can use multiple cores.

Concurrency vs parallelism ch4·s8–11

time → · Concurrency = several tasks making progress. Parallelism = several tasks running at the same instant.

  • Concurrency is possible on one core, because the scheduler switches between tasks. Parallelism needs several cores. You can have concurrency without parallelism.
  • Data parallelism: split the same data across cores and run the same operation on each part. Task parallelism: put different operations (threads) on different cores.
  • Multicore programming challenges: dividing activities, balance, data splitting, data dependency, testing and debugging.

Amdahl's law ch4·s12–13

speedup ≤ 1S + 1 − SN S = serial fraction · N = cores
App 75% parallel (S = 0.25)CalculationSpeedup
N = 11 / (0.25 + 0.75)1.00×
N = 21 / (0.25 + 0.375)1.60×
N = 41 / (0.25 + 0.1875)2.29×

The serial part has a disproportionate effect: no number of cores gets you past 1/S. Practise one example with different numbers, such as S = 0.4 and N = 4 → 1 / (0.4 + 0.15) ≈ 1.82×.

Thread libraries ch4·s21–32

A thread library gives programmers an API for creating and managing threads. It can live entirely in user space or be a kernel-level library supported by the OS.

Pthreads
A POSIX standard (IEEE 1003.1c). It is a specification, not an implementation. Can be user-level or kernel-level. Common on UNIX, Linux and macOS.
Windows threads
CreateThread() starts a thread, and WaitForSingleObject() waits for it, like join.
Java threads
Managed by the JVM, usually on top of OS threads. Create one by extending Thread or by implementing Runnable (the standard practice). start() runs it, join() waits.
Java Executor
Instead of creating threads yourself, submit tasks to an Executor. Callable + Future return a result.

Threading issues ch4·s49–57

fork() & exec()
Does fork duplicate only the calling thread or all threads? Some UNIXes have both versions. exec() replaces the whole process, including all threads. If you call exec right after fork, copying only the calling thread is enough.
Signal handling
A signal is generated by an event, delivered to a process, and handled by the default handler or a user-defined one that overrides it. In a multithreaded process it can go to: the thread it applies to, every thread, certain threads, or one designated thread that receives all signals.
Thread cancellation
Ends a target thread before it finishes. Asynchronous: terminate immediately. Deferred (the default): the thread checks periodically and only stops at a cancellation point such as pthread_testcancel(), then runs cleanup handlers. If cancellation is disabled, the request stays pending. Linux implements it with signals. Java uses interrupt().
Thread-local storage
Each thread gets its own copy of data. Useful when you don't control thread creation, such as in a thread pool. Unlike local variables, TLS is visible across function calls. It's like static data, but unique per thread.
Scheduler activations
M:M and two-level models use a lightweight process (LWP) as a virtual processor between user and kernel threads. Each LWP is attached to a kernel thread. The kernel informs the thread library through upcalls, so the app keeps the right number of kernel threads.

OS examples ch4·s58–62

Windows · one-to-one

Each thread has an ID, register set, separate user and kernel stacks, and private storage. Together these are the thread's context.

  • ETHREAD: executive thread block, points to its process and KTHREAD. Kernel space.
  • KTHREAD: scheduling and sync info, kernel stack, points to TEB. Kernel space.
  • TEB: thread environment block with thread ID, user stack and TLS. User space.
Linux · tasks

Linux calls them tasks, not threads. It creates them with clone(). Flags decide what the child shares with the parent (address space, files, signal handlers). struct task_struct points to process data that is either shared or unique.

Synchronization: the race condition ch3·s36–40

Go back to the producer–consumer buffer and add a shared counter so every slot can be used. The producer does counter++ and the consumer does counter--. Each statement looks atomic, but in machine code it is three steps:

StepWhoExecutesResult
S0producerregister1 = counterregister1 = 5
S1producerregister1 = register1 + 1register1 = 6
S2consumerregister2 = counterregister2 = 5
S3consumerregister2 = register2 − 1register2 = 4
S4producercounter = register1counter = 6
S5consumercounter = register2counter = 4 ✗ (should be 5)

A race condition happens when several processes or threads access and change shared data concurrently, and the result depends on the order in which they run. The fix is to make sure only one of them runs the code that touches counter at a time. This protected region is the critical section, guarded by tools like mutex locks and semaphores.

Slide question · ch3·s40

Why is there no race in the first version, which fills at most N − 1 slots? Because it shares no variable that both sides write. The producer only writes in, the consumer only writes out, and each just reads the other's. A race needs at least two writers to the same data.

Check yourself · week 4

What does a thread share with other threads in its process, and what does it keep private?
Shared: code, data (globals), open files and other resources. Private: thread ID, program counter, registers, stack.
Can you have concurrency without parallelism?
Yes. On a single core the scheduler switches between tasks, so they all make progress, but only one runs at any instant.
An app is 60% parallel. What is its speedup on 2 cores, and the maximum on unlimited cores?
S = 0.4. On 2 cores: 1 / (0.4 + 0.3) = 1.43×. Maximum: 1 / 0.4 = 2.5×.
Why can't many-to-one threads run in parallel on a multicore machine?
All user threads map to one kernel thread, and only one thread can be in the kernel at a time. If one thread makes a blocking call, all of them block.
Which threading model do Windows and Linux use?
One-to-one.
Asynchronous vs deferred cancellation: which is the default, and why is it safer?
Deferred is the default. The thread stops only at a cancellation point, so it can clean up and never leaves shared data half-updated.
How is thread-local storage different from a local variable?
A local variable exists only during one function call. TLS stays visible across function calls, but each thread has its own copy.
Using the S0–S5 interleaving, what other wrong value could counter end up with?
6, if the consumer's write (S5) happens before the producer's write (S4). The correct value is 5.
